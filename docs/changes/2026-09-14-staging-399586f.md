## Backend

### Stages
- New stage **`future_prospect`**: in `STAGES`, `_TERMINAL`, and the `rejected` segment (shown on the Rejected page).
- It's terminal, so qualify, follow-up and visit booking leave it untouched. Updated in `leads.py`, `huvo.py`, `huvo_calls.py` and `visits.py`.
- **`POST /v1/leads/{id}/stage`** sets any stage in either direction. It is the only stage write that isn't forward-only. It logs `stage_change` with before/after from `RETURNING`, and skips no-ops.

### Auto-assignment (`services/lead_assign.py`, new)
- Hourly sweep of `assigned_to IS NULL` (`LEAD_ASSIGN_INTERVAL_MINUTES = 60`, job id `lead_assign`).
- **City routing:** if some active RM covers the lead's city, a covering RM gets it; otherwise any RM does. There's no hardcoded city list: a city is valid if it's in some RM's `users.city`.
- **Balance:** the RM with the fewest leads assigned today (IST) goes first, then the longest since last assignment, then by name. Assignments made by other means today count too.
- Assigns one lead at a time (not set-based), and re-checks `assigned_to IS NULL` when claiming, so a manual assignment in progress wins.
- `role = 'rm'` only, never `test_rm`. Logs `assigned` with `metadata.source = "auto_round_robin"`.

### Activity log
| Event | Where | Notes |
|---|---|---|
| `lead_viewed` | `POST /v1/leads/{id}/viewed` | Deduped per person per lead over 30 min. Always 204. |
| source-data edits | `PATCH /leads/{id}/source-data` | One row per changed field, real before-values. |
| `assigned` on `wa_contact` | `gupshup_assign` | Records the previous owner, e.g. "unassigned → Asha". |
| `lead_created` (bulk WhatsApp) | `/gupshup/leads/bulk` | Previously not logged at all. |
| `meta_form_submitted` | Meta webhook (`_stamp_and_log`) | One per delivery, **including repeat submissions**. Logged in the same transaction as the lead stamp. Metadata: `meta_lead_id, form_id, campaign_name, ad_name, submitted_at, new_lead, answers`. |
| `lead_created` backfill | `scripts/backfill_lead_created.py` | Historical `created_at`, current source. Idempotent. |

### New endpoints

|---|---|---|
| `GET /v1/gupshup/pending` | user (thread-scoped) | WhatsApp conversations with no lead, for the notification bell. Excludes `rejected` contacts. Returns `last_inbound_at`; the client decides the 24h window. |

| `POST /v1/leads/{id}/viewed` | user | View logging (above). |
| `GET /v1/societies/all` | — | All `master_societies` names, for the Society filter. |

## Frontend

### Navigation and shell
- **Topbar is now an action strip**: page title, `TopbarSlot` for page actions (Select, Download CSV), incoming-call indicator, and the new **NotificationBell**.
  - Bell categories: New Leads · Reminder (callbacks due today, IST) · WhatsApp still replyable · WhatsApp template only.
- WhatsApp, Live Calls and Call Log moved into the **sidebar**. The unseen-incoming-calls count moved onto the Call Log nav item.
- Sidebar user chip shows identity only. Sign-out and the Light/Dark toggle live on the new **`/profile`** page.
- Global topbar search removed. Each lead list has its own `LeadToolbar` (city tabs, search, Filters, Select). Inventory and Supply got local search boxes. Mobile keeps its global search.
- Page transitions, skeleton loaders (`Skeleton`), and 50-row paging (`Pager`).

### Home (replaces Dashboard)
- `pages/Home.tsx` with a **Summary / Table** toggle, remembered per browser.
- **Summary → `LeadFunnel`:**
  - Bars: All → Qualified → Visit → Revisit → Closed, plus **Future Prospect** below, set apart. Each bar is its own current count.
  - Side band "Other stages": New · Call Not Received · Call Back Again · Rejected (excluding future prospects), so bars + band = All.
  - Filters: range (This week / This month / All time / Custom, IST) and an admin-only RM dropdown.
  - Guard: `node scripts/check-funnel.mjs`.
- **Table → `AllLeads`:** every lead, with clickable stage count boxes. Counts wait for all 8 segment queries to load.

### Lead detail popup
- Clicking any lead row opens `LeadModal`. The route `/leads/:id` still works (new tab, pasted link).
- Cards:
  - Status | Follow-ups
  - Meta form (or source data) | Remarks
  - Confirmed-on-call form
  - **Lead history**, from `activity_log`, via the shared `lib/activity.tsx`
- `MetaFormCard` shows the real Instant Form answers plus campaign/ad. On webhook leads it replaces the editable source-data card.
- Manual stage picker (all stages, including Future Prospect).
- Removed: WhatsApp button, `WaLeadCard`, inventory/supply match panels, and the English/Hinglish office-visit pitch (also removed from `HANDOVER.md` / `INTERFACE.md`).

### Lead-list filters (`lib/leadFilters.ts`, `components/FilterBar.tsx`)
- **On every lead list:**
  - Society (from `master_societies`)
  - Created (date range)
  - Assigned (date range)
  - Meta form yes/no
  - Invalid number yes/no (not 10 digits after a real `+91`)
  - Assigned RM (lists every RM, including those with 0 leads)
- **Home and Rejected also get:** Rejected stage (Rejected / RNR / Future Prospect), Reject reason, Rejected on.
- `FilterBar` gains a `daterange` field type.
- Guard: `node scripts/check-lead-filters.mjs` (runs the real module).

### Other page changes
- **Select mode:** checkboxes and the bulk-assign bar only appear after pressing Select, with "select first 10 / 25" shortcuts.
- **Lead tables:** separate Lead / Phone / Source columns, call button beside the number, tighter column sizing.
- **Analytics:** RM-only "My performance" card. RNR and Future Prospect are subtracted from Rejected. AI summary panels removed.
- **Huvo calls:** summary clamped to one line with expand. "No campaign" filter option.
- **Chat:** `?phone=` opens a specific conversation (used by the bell).
- **Call log:** changing a filter resets paging. Recording links open the audio in a new tab.
- **Meta Leads page:** CSS moved to `.ml-*` classes; selected row and status filter fixed.
- **WhatsApp:** shared 24h-window rule and access gate in `lib/wa.ts`.
- **Visit planner / Inventory poster:** kept literal colours (Google Maps and html2canvas can't read CSS variables).
